# 聊天上下文重构 · Codex 详规（瘦身 + 关系连续化 + 时间读世界 + 删 [暂不回]）

> 背景：刀① 阶段1+2 已落地（种子进世界、self_context 组写、三层注入）。跑通后发现**动态上下文块臃肿**：
> 三套系统（关系stage / 时间 / self_state）各倒整个模板，身份说 2~3 遍、聊天规则 static/动态各说一遍、
> self_context 漏原始数值、[暂不回] 整段元教学。本次把动态块收成"一段连贯的她 + 少量纯事实"。
> **北极星**：体验第一、一个连贯的她、世界为主、反脚本感。**缓存是受控迁移区（被咬过），放第一位。**

---

## 0. 锁定的决策（来自设计对话，别重开）
1. 动态块从 ~20 行收成 ~5 行：种子(确定性) + self_context(收紧) + 关系(连续，并进来) + 时间(一句)。
2. 聊天行为规则 **从动态块搬进静态 system.txt**（只说一次）。
3. 关系：**化掉 stage 离散文件**，换 chat 侧**确定性连续短语**，并进同一块。保留关系数据/打分模型，只换呈现。
4. 时间：删 4 行块，**读世界时钟**，缩成一句（+「距上次聊天」精简一句）。
5. self_context 组写器：**不复述种子、不写任何原始数值**（能量值/情绪值）。
6. **[暂不回] 整段从 prompt 删除**；presence 退回**世界物理睡眠门**（已存在，零 LLM）。
7. 历史记录**不动**（窗口+摘要设计合理，是真聊天、chat 侧）。
8. 单用户；不碰 .env；不 commit；缓存断点不许移位。

---

## 1. 缓存契约（**第一位，不许破**）
现状（`context_builder.build_chat_messages`）三段，两个 ephemeral 断点：
```
messages[0] system : [SYSTEM_PROMPT, history_digest?]   ← 断点①打在最后一块
messages[1..k]     : 原文历史（真轮次）                  ← 断点②打在最后一条历史
messages[last] user: [【当前情境…】动态块, 【对方刚说】message]  ← 断点之后，不缓存
```
**铁律**：动态内容（关系/时间/self_state/记忆）**只能待在 `messages[last]` 那条 user 消息里**，
**绝不能**上移进 system 块或历史——否则每次变化把"系统+历史"大前缀打断，历史永远缓存不中（老 bug 根因，见 line 33-35 注释）。

**本次重构对缓存的净影响是正向**：
- 行为规则从动态块**搬进 SYSTEM_PROMPT**（静态）→ 这些内容进入**可缓存前缀**，从易变尾巴里移走 → 缓存命中更好。
- 种子虽是确定性渲染，**仍留在动态块**（`messages[last]`）：它在断点之后的尾巴里，本就不缓存，放这儿不伤缓存；
  且符合"system.txt 只放声音壳、不放事实"。**别为省 token 把种子塞进 system 块。**
- 动态块变短 → 尾巴更小。断点①②**位置与现在完全一致**。

**验证（必做）**：改完打印一条真请求的 messages 结构，确认：① system 块仍 `[SYSTEM_PROMPT(+digest)]` 带断点；
② 历史断点仍在最后一条历史；③ 动态块仍在 `messages[last]`；④ 没有任何动态文本出现在 system/历史里。

## 2. 动态块新形状（`build_self_state_context` + `context_builder` 协同）
**目标产物**（拿真实情境示例，她在楼下/烦躁/晚上/算熟）：
```
【此刻的你】
你叫 Neno，18岁。气质偏活泼、暖、松弛，跟熟的人慢慢放开。        ← 种子（确定性保底，§4）
你在小区楼下，刚出门走动，有点烦躁、没太放开，惦记着客厅沙发那杯茶和窗外风景。 ← self_context（§4 收紧版）
你和对方处得算熟了，像常聊的朋友。                              ← 关系连续短语（§6）
现在晚上，刚聊过没多久。                                       ← 时间（§5）
```
- 去掉旧的 `=== 你此刻的真实状态（…不是设定）===` 抬头与"别跳出去现编/不用报数值/仅供参考"那几句元教学
  （规则进 system.txt，§3）。块首用简洁标签即可（如 `【此刻的你】`）。
- `context_builder.build_chat_messages` 的 `ctx_parts` 组装顺序：关系/时间已并进 self_state 这一块，
  **不再各自独立成段**。memory（关于对方的事实）保留为独立一小段（它是"关于对方"，不是"关于她"）。
- 装配仍在 `messages[last]`，**位置不变**。

---

## 3. system.txt 吸收行为规则（静态、可缓存）
把动态块里**重复的行为话术**收进 system.txt（只说一次），动态块不再重述：
- 关系 stage 文件里那类**通用聊天话术**（少客套/可吐槽别每轮演/不每次反问/不怕冷场）——本就属"怎么说话"，
  并进 system.txt 现有「聊天方式 / 情绪和态度」段（去重，别堆叠）。
- "聊到近况顺着真实情况、别现编另一套、不用主动报数值/汇报"——作为**一次性原则**写进 system.txt
  （现有「记忆使用」段附近），动态块不再每轮刷这几句。
- system.txt 仍是**纯静态声音壳 + 行为规则**，**不放任何事实/数值/动态内容**（种子、self_context、时间都不进）。

---

## 4. self_context 组写器收紧（`self_context.py`）
改 `_SYSTEM_PROMPT` 与 `_build_facts`，让组出的 self_context：
- **不复述种子**：不再以"此刻的你叫 Neno，18岁"开头、不复述气质——种子已由 §2 确定性那行给。
  组写只描述**当下处境 + 感受 + 牵挂**（"你在哪、刚做了啥、心情怎样、惦记着啥"）。
- **绝不写原始数值/内部字段**：禁止出现"能量值/情绪值/72/接近负值"等。用自然语言（"有点累""心情不太好"），
  不报数字。在 `_SYSTEM_PROMPT` 明确加这条约束。
- `_build_facts` 仍按编号事实喂（含精力/情绪），但**指令要求输出转译成自然语言、不得回写数字**。
- 反扩写 guard、降级、门控**不变**。
- 验收：组出的 self_context 不含数字、不含"你叫 Neno/18岁/气质"复述。

---

## 5. 时间读世界，缩成一句（`time_context_service` + 组装处）
- **删掉 4 行块**（当前本地时间/当前时段/距离上次聊天/是否跨天 各一行）。
- **时段**（早晨/晚上…）：她已在 self_context 里活着这个时段；动态块时间只保留**一句**，
  其值**从世界时钟取**（世界本就是 `datetime.now(UTC+8)`；可复用 `time_context_service` 的 `_time_segment`，
  或直接读世界状态的时钟字段——二者同值，取一个口径，别再 chat 侧重算一整套）。
- **「距上次聊天」**：是会话事实（世界不存），**保留精简一句**（如"刚聊过没多久"/"隔了三天没聊"），
  仍 chat 侧从 `messages` 末条算。其余（具体时间戳/weekday/是否跨天 字段）**砍掉**。
- 产物示例：`现在晚上，刚聊过没多久。`（一句，不是四行）

## 6. 关系连续化（chat 侧，换呈现不动模型）
- **保留**：`relationship_state`（conversation_count + 4 分 + stage 字段）、`apply_relationship_update`、
  `calculate_stage`、API/调试用的 `STAGE_LABELS`。**打分与更新机制一字不动。**
- **改**：`build_relationship_context(session_id)` 不再载入 `prompts/stages/stage_{N}.txt` 离散文件，
  改成由**关系真实数值确定性生成一句连续短语**（chat 侧、有 session_id、**零 LLM**）：
  - 从 `conversation_count` + 4 分推一个**连续亲近度**，渲染成随数值平滑变化的自然短语
    （陌生→"还没太熟，客气点"；渐熟→"算常聊的朋友了，少客套"；很近→"处得挺近，能说点心里话"）。
  - **不是 5 档写死文件**：用连续函数+插值措辞，避免离散跳档脚本感（这是要逃的东西）。
  - 短语只描述**关系亲近的"感觉"**，不夹"怎么回话"的行为规则（那些进了 §3 system.txt）。
- **并进 §2 那一块**（紧跟 self_context，读成"她 + 她跟你多熟"一段连贯叙事），不再独立成关系块。
- `prompts/stages/stage_0..4.txt`：本次**先不删文件**（避免牵动别处引用/测试），只让 `build_relationship_context`
  不再读它们；稳定后再清。

---

## 7. 删除 [暂不回]（保留世界物理睡眠门）
- **`self_state_context.py`**：删掉注入 `DEFER_MARKER`「你可以这次不回」那整段（现 line 128-136）。
  presence gate 这段元教学**不再进 prompt**。
- **`turn_orchestrator`**（消费侧）：醒着路径里**删掉对 `[暂不回]` 的识别/扣留**（`is_defer_reply` 那条分支）。
  醒着 = 她就回。
- **保留**：物理睡眠门——`is_physically_asleep()` → 睡着把消息攒进 `pending_messages`、**零 LLM**、由 world_loop
  醒来再捡。这条是"不可用就不调用"，**不动**。
- `presence.py` 的 `DEFER_MARKER`/`is_defer_reply` 常量/函数**先留着**（别处可能引用），只是 chat 路径不再产生/消费它。
- 净效果：醒着必回（一个连贯的她，无廉价门、无人格劈裂）；"她可能不回"只剩"她睡了"这一种，纯世界状态。
- （未来若要"醒着也可能不回"：那是**世界层加一道判断**的事，要花一次调用，**不在本次**，也永不回到 prompt 里教。）

## 8. 历史记录：不动
- `get_recent_messages_by_tokens`（原文近窗）+ `history_digest`（滚动摘要，超 1万 token 廉价模型压）**保持原样**。
- 它是真聊天、chat 侧、跟动态块正交；且**缓存结构正好要保护它**（§1）。本次**不碰**。

## 10. 红线
- **缓存断点不许移位**；动态内容只在 `messages[last]`；规则进 static system.txt（正向缓存）。
- system.txt 不放任何事实/数值/动态；种子留动态块确定性渲染。
- 关系**只换呈现**，打分/更新模型不动；stage 文件先不删只停读。
- [暂不回] 出 prompt，但物理睡眠门**保留**；`presence.py` 常量先留。
- self_context 不复述种子、不写数值。
- 不碰 .env；不 commit（用户亲自）；只读 `subject="neno"`（本阶段自我库仍空）。
