# 方案：世界视图升级为真正的 2D 场景引擎

> 起因：分层独立件 → 反应式物品 → "需要物理引擎"。本方案回答：到底需不需要物理引擎、
> 该怎么搭、美术怎么配、分几步走。**Python 世界引擎(权威模拟)不动,只换"视图层"。**

## 一、先厘清：你需要的是"2D 引擎",物理只是其中可选一块

| 你要的 | 靠什么 | 需要物理引擎吗 |
|---|---|---|
| 每件独立、可单独换/动 | 场景图 + 精灵系统 | ❌ |
| 状态变化（壶 cold→boiling、灯 on/off） | state→精灵切换 | ❌ |
| 常驻微动（呼吸/摇摆） | 补间动画(tween) | ❌ |
| 操作手感（弹一下） | 补间 | ❌ |
| **有机次级运动**（风铃摆、窗帘飘、挂植晃、东西掉落弹、布料/头发） | 弹簧/verlet 物理 | ✅（锦上添花） |

**结论**：地基是 **2D 场景图 + 精灵系统**；物理只在"自然次级运动"上加分，是可选模块，不是前提。
你说"需要物理引擎"，本质是想要一个**真·活的 2D 世界**——那答案是：上一个**自带物理的 2D 引擎**。

## 二、两条路

### A. 留在 DOM / CSS（延续现在）
- ✅ 不重写、已经跑着、简单。
- ❌ 几十上百个动画件性能吃力；物理基本做不了；层级/相机/合成/碰撞都要手搓。
- 适合：只想要"贴片 + 微动"，不追物理和大规模精灵。

### B. 上真正的 2D 引擎（推荐）
浏览器变"薄客户端"：**每拍读 Python 快照 → 引擎按每个物品 state 渲成精灵、播动画、(可选)挂物理**。
- **Phaser 3**（推荐）：完整 2D 游戏引擎，自带场景/精灵/相机/输入/**物理（Arcade 轻量 + Matter.js 真物理）**/粒子。物理开箱即用。
- **PixiJS**：纯 WebGL 2D 渲染器，更轻更快，适合海量精灵+图层+滤镜；要物理另接 matter.js。
- ✅ 分层/相机/精灵/物理/粒子/性能全现成；真·活的世界；以后交互/光照/天气都顺。
- ❌ 视图层要重写（现在的 DOM world-view 换成引擎场景）；引入一个库 + 学习成本。

**推荐 B + Phaser**：你已经在想物理，说明要的是真 2D 世界；Phaser 自带物理，Python 当后端，分工干净。
（若确定不要物理、只要海量精灵流畅 → PixiJS 更轻。）

## 三、架构（B 路）
```
Python 世界引擎(权威模拟，不变)
        │  每拍 /world-live 快照(已含 rooms/objects/state/category)
        ▼
浏览器 Phaser 客户端(薄、纯呈现)
  - 场景 = 房间壳(背景层) + 城市夜景层(窗后) + 物品精灵层(每件独立)
  - 渲染器：遍历快照物品 → 按 state 选精灵帧 → 摆到坐标 → 播 idle 动画
  - 物理(可选)：风铃/窗帘/挂植/掉落 挂 Matter.js
  - 相机：跟着她在房间间平移(沿用现有逻辑)
```
**关键**：和现在 DOM 版是同一套思路（状态→渲染的纯函数），只是渲染器从 DOM 换成 Phaser，
拿到"图层/精灵/物理/相机/性能"的现成能力。`OBJECT_SLOTS`/`STATE_FX`/`autoLayout` 这些配置可直接迁移。

## 四、美术（配合"单独的件"）
- 一套**统一 lofi 风的精灵资产**（风格已选对：治愈日系/lofi）：
  - **9 个房间壳**（墙/地/窗框，空的）+ **窗后夜景层**（可换昼夜）
  - **共用道具库**：杯/书/台灯/绿植/椅子…**出一次到处复用** → 100+ 砍到 ~40 独立道具
  - **各房间特有件** + **状态变体只给会变的**（壶 cold/boiling、植物 fresh/wilt/dead）
- 产法：每件单独出（透明底 + 统一风格锚），或"整图再切"（出一张统一场景 → 抠成层）。
- 量级估：~9 壳 + ~40 共用道具 + ~30 特有/状态件 ≈ 80 张（远小于 112×状态）。

## 五、分步落地
1. **选型**（A/B + 引擎）——你拍板。
2. （若 B）搭 Phaser 骨架：读快照 → 渲一个空场景 + 相机。
3. **客厅一间走通**：房间壳 + 几个独立精灵 + 状态变化 + 一点物理（挂植 verlet 摆、台灯静止）。
   验证"她后台动手 → 精灵当场变"在引擎里跑通。
4. 铺**共用道具库** + 其余 8 间。
5. 物理/粒子/光照/天气按需加。

## 六、风险与成本
- 视图层重写（现有 DOM world-view 替换）——但 Python 后端、快照协议、slot/状态配置都复用。
- Phaser 学习 + 集成（中等）。
- 美术资产仍是大头，但"共用库 + 状态只给会变的"能压到 ~80。
- 不影响任何后端/聊天/主循环。

## 七、建议
**B 路 + Phaser，先拆客厅一间走通**（含 1-2 个物理件让你看"有机运动"长啥样），
跑通了你再决定铺不铺满。先验证手感和工作量，再投美术。
