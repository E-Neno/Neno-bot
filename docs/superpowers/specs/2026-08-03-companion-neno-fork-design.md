# 陪伴 Neno 独立分叉设计

## 目标

在 `C:\Users\hxie7\Desktop\neno-companion` 建立一个独立运行的陪伴版 Neno。它明确是 AI，重点是日常聊天与情感支持，不模拟真人生活，也不以故意沉默、生活汇报或身份隐瞒制造真人感。

## 选定方案

采用“完整项目副本，运行时裁剪”的两阶段方案。

- 第一阶段复制现有项目，保留已验证的聊天、记忆、会话串行化、多模态输入与 OpenClaw 微信桥。
- 陪伴版改用 `prompts/neno_companion_prompt.md`，并使用独立的 `.env`、SQLite 数据库路径、上传目录、日志目录和端口。
- 世界引擎、日计划、生活主动循环和类真人决策路径默认关闭，且不作为陪伴版的产品能力。
- 第二阶段仅在聊天与桥接验证通过后，评估删除未使用模块；第一阶段不删除承重代码，避免破坏现有聊天状态契约。

## 运行边界

陪伴版必须与原 Neno 隔离：不共享运行数据库、`history_digest.json`、上传文件、日志或环境文件。微信 OpenClaw 桥使用陪伴版自己的 Neno HTTP 入口与白名单文件。企微 Bot 保留为可选备用入口，但不作为本次验收条件。

聊天仍遵守原有 Session 串行化、摘要游标单调递增和缓存安全提示词装配顺序。陪伴版不启动 `WorldLoop`，不把 `life_world_state`、类真人自我状态或主动生活行为送入聊天。

## 用户体验

陪伴版的回复优先顺序是：听清用户在说什么，接住情绪，陪其展开或梳理，在用户明确需要时提供可执行的建议。它可以有亲近感和 Neno 的语言风格，但不宣称自己是人，也不使用刻意冷处理维持关系张力。

初始微信能力为文本回复、图片输入理解和语音输入转写。图片/语音的主动输出不在本次范围。

## 实施与验证

1. 复制项目到独立目录，排除运行数据、虚拟环境、缓存、Git 内部目录和原 `.env`。
2. 生成陪伴版本地环境配置，替换提示词路径、状态路径及监听端口，并显式关闭世界和类真人相关开关。
3. 将 OpenClaw 桥的本地 Neno endpoint 指向陪伴版，保留原版桥配置不变。
4. 通过单元测试、配置断言和一条本地平台文本消息验证：新会话只写陪伴版状态，能正常返回陪伴版文本。

## 非目标

- 不修改原 Neno 的聊天、世界或提示词装配逻辑。
- 不实现个人微信协议、付费协议服务或任何授权绕过。
- 不实现微信端图片、语音、视频或文件的主动输出。
