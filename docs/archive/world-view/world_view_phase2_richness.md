# 世界视图 · 第二阶段：从"一张图"到"活的场景"（给 Codex）

> 前提：v1 已接通后端（`world-view.css` / `worldViewAdapter.js` / `/test`，跟随镜头 + 房间 PNG 作 L0 + 单姿势立绘）。
> 本阶段目标：在那张静态图上叠"会动的层"，让它从看一张照片变成看一个人在房间里过日子。
> 红线不变：纯前端为主；复用现成只读端点；要补字段只能往 `build_snapshot()` 只增不删；不碰 6 个红线文件；不改 DB schema。
> 完成标准：**你亲眼看着像她在过日子**，不是接口通。每条做完都能独立验收。

## P1 · 时段光照（最高优先，零美术，立竿见影）

让**同一张 PNG**随 `sim_time` 在一天里变光。这是把"照片"变"有时间流动的空间"最便宜的一招。

**实现**：在 `.viewport` 上加一个全局叠层 `.daylight`（盖住所有房间，`pointer-events:none`，`z-index` 在房间之上、角色之下），按小时改它的渐变色与混合：

```js
// worldViewAdapter 里，拿到 world.sim_time 后：
function dayGrade(hhmm){
  const h = parseInt((hhmm||"12:00").split(":")[0],10);
  // [色调, 不透明度, 混合模式]，中间值可线性插值
  if (h<5)  return ["#0e1430", .55, "multiply"];   // 深夜 冷暗
  if (h<8)  return ["#ffcaa0", .22, "soft-light"];  // 清晨 暖金
  if (h<16) return ["#fff4e0", .06, "soft-light"];  // 白天 通透
  if (h<19) return ["#ff9e6b", .30, "soft-light"];  // 黄昏 橘
  if (h<22) return ["#2a2350", .38, "multiply"];    // 入夜 紫
  return ["#0e1430", .52, "multiply"];              // 夜 冷暗
}
// 应用：.daylight { background: 色; opacity: 透明度; mix-blend-mode: 模式 }
// 加 transition: all 1.5s 让跨时段平滑过渡
```

**配套**：入夜后（h≥19 或 h<6）给"灯开着"的房间叠暖光晕（数据：`rooms[x].objects` 里 lamp/ceiling_light 的 `state==="on"`），白天不显。

**验收**：手动 `world-tick` 推几步，看一整天从晨到夜光线在流动；当前房间始终最亮。

## P2 · 她真动起来 + 坐到家具上（信任感最大修复；有美术依赖）

现在她"读书"是站在房间中央缩小——最假的地方。分两步，**第 1 步无需美术就能先修一半**。

**P2a（先做，无美术）：把她"放"到家具上**
给每个可坐/可用物件加"落座锚点"，动作匹配时她移动到锚点而非房间中央：

```js
// 房间内归一化坐标 [x, y]（y 控制她坐下时下移到家具上）
const SEAT = {
  read_book:  { obj:"sofa", x:.52, y:.72 },   // 坐沙发
  sleep:      { obj:"bed",  x:.30, y:.62 },   // 躺床
  water_plant:{ obj:"plant",x:.78, y:.58 },
};
// applyState 里：若 last.action 命中 SEAT，用其 x/y 覆盖默认站位，
// 并按 y 微调 bottom，让她"贴"在家具上而不是浮在地板中间。
```

**P2b（要美术）：补核心姿势立绘**
按 `world_view_spec.md` §4，至少补：`idle / walk / sit-read / sleep`，透明底、统一光向（暖光、左上方向，跟房间一致，减轻"贴纸感"）。`worldViewAdapter` 的 `poseOf()` 已能选帧，到位后把缩放占位换成真立绘即可。
> 接触阴影已有 `drop-shadow`，建议再加一小片椭圆地面投影，进一步把她"焊"在地上。

**验收**：她读书时**坐在沙发上**、睡觉**躺在床上**；走动时是走路姿势。

## P3 · 环境动效 + 天气 + 窗外（大多纯代码）

让屋子自己呼吸。按 hook 逐条加（steam 已有可参考）：

- **灯火轻闪**：有灯房间叠 `@keyframes` 让灯晕 opacity 微动（5s 慢）
- **电视幽光**：客厅 tv `state==="has_unread"` 时叠一块蓝白微闪
- **窗帘微摆 / 绿植轻晃**：低幅 `transform` 循环（≥3s）
- **窗外城市入夜亮灯**：夜间在窗区叠"随机点状灯光"层（参考 concept 里 `.city`），白天隐
- **天气/雨**：当前 `rain` 是写死装饰。要联动需后端 `weather` 字段——**后端没有**。两选一：
  - v2：先把 rain 接到时段或留手动开关（不依赖后端）
  - 后续：`build_snapshot()` **只增** `weather`（接 `LifeEventSource` 的天气事件），前端按它开雨/雪
- **猫（强烈建议，纯前端，最提活气）**：一个独立小精灵，自己在房间带里随机走动/趴下/追光，跟 Neno 状态无关。一段独立 setInterval + 随机目标即可。

**验收**：她不动时，屋子也在轻轻动（灯、窗帘、窗外、猫），不再是死的。

## P4 · 景深视差（可选，锦上添花，有处理成本）

把每张房间 PNG 切成 前景/中景/背景 3 层，镜头平移时各层位移速度不同 → 3D 纵深。需要按层重导出或抠图，成本较高，**放最后**。

---

## 后端要不要动？

- P1 / P2a / P3(除天气) / P4 / 猫：**全前端，后端零改动**。
- P2b：纯美术资源，无后端。
- 天气联动：可选，且只能 `build_snapshot()` **只增** `weather`，不碰别的、不改 schema。

---

## 建议落地顺序（每条独立可验收，随时能停）

1. **P1 时段光照** — 半天，零美术，整个场景立刻"有时间"
2. **P2a 坐到家具上** — 零美术，先把最假的地方修掉一半
3. **P3 环境动效 + 猫** — 纯代码，屋子开始自己呼吸
4. **P2b 真姿势立绘** — 等美术，到位后替占位
5. **天气联动 / P4 视差** — 可选，最后

> 一句话：先把"光会变、她坐下了、屋子在动、有只猫"做出来（基本免费），它就从"一张图"变成"一个活着的房间"了。真姿势立绘和视差是后续打磨。
